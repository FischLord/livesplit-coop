Second public testing beta of **LiveSplit Coop**. It fixes viewer safety issues, makes connections recover faster and cuts ongoing traffic to a small clock tick between changes.

## ⚠️ Breaking: protocol v2

0.1.0-beta.2 uses **protocol v2** and cannot talk to 0.1.0-beta.1. Update the relay **and** every host/viewer component together. An outdated client is refused with a message asking to update LiveSplit Coop.

## Downloads

- **LiveSplit.Coop-v0.1.0-beta.2.zip:** native LiveSplit component and documentation. Copy `Components/LiveSplit.Coop.dll` into an existing LiveSplit installation, replacing the beta.1 DLL.
- **LiveSplit.Coop-relay-v0.1.0-beta.2.zip:** Node relay source, lockfile, Dockerfile, separate HTTP/direct-TLS Compose examples and deployment documentation. Existing `rooms.json` files keep working.
- **SHA256SUMS.txt:** checksums for both archives.

No hosted endpoint, working room credentials, LiveSplit application binaries, game autosplitters, personal PBs or saved runs are bundled.

## Fixes

- **Autosplitter guard for viewers now works.** Scriptable Auto Splitter (`ASLComponent`) and Auto Splitting Runtime (`ASRComponent`) were not detected by beta.1. Viewer mode now refuses to start with them and stops if one is added while viewing. Host layouts are unaffected.
- **Splits loaded or edited while viewing are never overwritten.** Viewer mode stops instead of writing host times into them, and the newly loaded splits stay loaded after disconnect.
- **Host reconnects immediately.** A new connection with the host key replaces a stale host connection (close code 4001); the replaced component stops rather than fighting back. Previously a silently dropped host could be locked out for up to about 30 seconds.
- **Viewers can no longer occupy the host slot**, and a host takeover also works when the relay is at its connection limit.
- **Silent unauthenticated sockets cannot block the relay.** They no longer count against the member limit; the oldest waiting socket is dropped when the waiting pool is full. TLS handshakes time out after 10 seconds.
- **Dead connections are detected by the client** after 15 seconds without any relay message, instead of waiting for TCP.

## Changes

- Complete snapshots are only sent when something besides the clock changes or after reconnecting; otherwise the host sends a tick of about 100 bytes four times per second. The relay merges ticks so late joiners still receive the complete state, and serialises each broadcast once for all viewers.
- Viewers apply ticks without rebuilding their run.

## Validation and known limits

Tested against LiveSplit 1.8.34 / Windows .NET Framework 4.8: 13 relay integration tests, 35 native checks against a loopback relay and 17 checks with three real LiveSplit windows passed with protocol v2. The public WSS checks documented for beta.1 have **not** been repeated with v2 yet.

**This is still a beta, not a verified full-game release.** A complete real Duo/Trio game run remains outstanding. All other limits from beta.1 still apply: running digits can trail the host by network delay, histories/icons/scripts/layouts are not transmitted, the relay cache is in memory only, and access keys are shared per role without individual revocation.

Please report reproducible issues with versions, role and timing method, without access keys or private run data.
