Third public testing beta of **LiveSplit Coop**. Nobody in the group has to run a server anymore: the host creates a room with one click on a community relay and shares an invite code; teammates join with one click. Still nothing but the component is installed on player PCs, and no VPN or port forwarding is needed.

## ⚠️ Breaking: protocol v3

0.1.0-beta.3 uses **protocol v3** and cannot talk to 0.1.0-beta.2 or beta.1. Update every host and viewer component, and a self-hosted relay, together. Older clients connecting to a v3 relay are told to update.

## Downloads

- **LiveSplit.Coop-v0.1.0-beta.3.zip:** native LiveSplit component and documentation. Copy `Components/LiveSplit.Coop.dll` into an existing LiveSplit installation, replacing the old DLL.
- **LiveSplit.Coop-relay-v0.1.0-beta.3.zip:** for self-hosting only. Node relay (source, lockfile, Dockerfile, Compose examples) and the Cloudflare Worker variant (`relay-cloudflare/`). Existing `rooms.json` files keep working.
- **SHA256SUMS.txt:** checksums for both archives.

No working room credentials, LiveSplit application binaries, game autosplitters, personal PBs or saved runs are bundled.

## New

- **Create room (host):** makes a private room on the configured relay and fills in room, role and host key. The host sees an **invite code** (`lscoop:1:…`) with a Copy button.
- **Join with invite:** teammates copy the invite and click the button (or paste it into the Room field); server, room, role and viewer key are filled in. The invite never contains the host key.
- **Community relay preset:** new components point to `wss://livesplit-coop-relay.janneck.workers.dev/coop`, a Cloudflare Worker with one Durable Object per room. It is a closed beta without availability guarantee; rooms are deleted after seven days without a connection. The relay operator can technically see timer data (splits, PBs, game, category); there is no end-to-end encryption. Existing layouts keep their configured server.
- **Self-hosted relays** can offer room creation with `ROOM_CREATION=1`; rooms from `rooms.json` never expire.

## Changes and fixes

- Settings are organised in three steps (Room, Role and key, Connect) and fit LiveSplit's settings tab without horizontal scrolling. The former unreachable example server, which caused a connect/retry loop, is gone.
- The HUD distinguishes joining, retrying and stopped. Wrong keys, an unsupported protocol and unknown or expired rooms (new close code 4004) stop with a clear message instead of reconnecting; a full room keeps retrying.
- A viewer with an active autosplitter is told where to fix it (Edit Splits → Deactivate, or remove Scriptable Auto Splitter from the layout), already when the invite is applied.
- Build and test scripts accept a LiveSplit path with a trailing backslash.

## Validation and known limits

Tested with LiveSplit 1.8.37 / Windows .NET Framework 4.8: 21 Node relay tests including a conformance suite shared with the Cloudflare relay (6/6 in local workerd), and 57 native checks. The native suite also passed against the Worker locally. Over the public community relay, a host created a room, a viewer on another LiveSplit joined by invite, and start and pause arrived. Splits, undo, reset, finish, host loss and reconnection have not been repeated over the public relay yet, the three-window test was not rerun for v3, and Durable Object hibernation is untested.

**This is still a beta, not a verified full-game release.** A complete real Duo/Trio game run remains outstanding. Running digits can trail the host by network delay; histories, icons, scripts and layouts are not transmitted; access keys are shared per role without individual revocation. Some networks (for example corporate proxies) block `*.workers.dev`.

Please report reproducible issues with versions, role and timing method, without access keys, invite codes or private run data.
