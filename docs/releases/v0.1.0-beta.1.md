First public testing beta of **LiveSplit Coop**: one authoritative host timer, multiple native LiveSplit viewers, and a relay you host yourself. No VPN or desktop companion is required.

## Downloads

- **LiveSplit.Coop-v0.1.0-beta.1.zip:** native LiveSplit component and documentation. Copy `Components/LiveSplit.Coop.dll` into an existing LiveSplit installation.
- **LiveSplit.Coop-relay-v0.1.0-beta.1.zip:** Node relay source, lockfile, Dockerfile, separate HTTP/direct-TLS Compose examples and deployment documentation. Requires operator setup and newly generated room keys.
- **SHA256SUMS.txt:** checksums for both archives.

These are generic public packages. No hosted endpoint, working room credentials, LiveSplit application binaries, game autosplitters, personal PBs or saved runs are bundled. The host keeps their own game setup.

## Included

- One publisher per room with separate host/viewer keys.
- Full snapshots including previous checkpoints, PBs, best segments and named comparisons; late joining and automatic reconnection.
- Real Time, optional Game Time, pause/resume, skipped splits, undo, reset and exact completed split/final values.
- Temporary viewer run; disconnect restores the original local run.
- Visible offline state with a frozen timer, TLS transport and DPAPI-encrypted client settings.
- Optional direct TLS with certificate reload, or deployment behind an existing reverse proxy.

## Validation and known limits

Tested against LiveSplit 1.8.34 / Windows .NET Framework 4.8. Seven relay integration tests, 24 native checks locally and over a public WSS deployment, and 17 local three-window checks passed. The live deployment used rootless Docker and Node 24. TLS rotation and invalid replacement handling have automated coverage.

**This is a beta, not a verified full-game release.** A complete real Duo/Trio game run remains outstanding. The extra WAN GUI run could not initialize on a locked desktop; the successful native WAN checks are separate evidence. Third-party components dependent on local timer events or complete segment history need compatibility testing.

Running digits can trail the host by network delay; completed split/final values match exactly. Game-specific metadata, icons, complete attempt/segment histories, scripts and layouts are not transmitted. Viewers do not automatically archive results; the host must save their `.lss`. Relay cache is in memory only. Connections start manually. Access keys are shared per role, without per-person accounts or individual revocation. Intended initially for small trusted groups using their own TLS relay.

Please report reproducible issues with versions, role and timing method, without access keys or private run data.
