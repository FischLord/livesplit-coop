First stable release of **LiveSplit Coop**: one player measures the run, teammates see the same splits in their own LiveSplit windows. Nothing but the component is installed on player PCs, and no VPN or port forwarding is needed.

## Highlights

- **Lobbies with a name and an optional password.** The host creates a lobby in the coop window; teammates join with the name and the password. The password never leaves the PC: both sides derive the viewer key from name and password.
- **Public lobby list.** A host can show the lobby in a public list. Viewers pick it from the list (with a lock for password-protected lobbies and the host/viewer count) or type the name.
- **One "Coop..." window.** Right-click the timer and choose **Coop...**: create or join, copy name and password, leave, reconnect, and the **Advanced** section (server, invitation codes, diagnostics export). The window is lobby-only and game-agnostic.
- **The lobby is remembered.** It is stored in `coop-local.json` next to `LiveSplit.exe` (protected with Windows DPAPI) and reconnects automatically when LiveSplit starts. You no longer need to save the layout; layouts only hold the role.
- **Viewers record into their own splits.** Attempts a viewer follows are saved to the viewer's own splits file, and a faster host PB is taken over faster, on first contact.
- **Optional profile packs.** A game package can ship a `coop-profiles.json` that maps game/category to splits and layout. The host's profile label shows in the public list.
- **The host sees the viewer count** in the coop window and in the status line.
- **Failed-login lockout.** The relay blocks repeated wrong passwords for a short time; the client says so instead of retrying.
- **English and German UI.** English by default, German when the Windows display language is German. Status lines, errors and dialogs follow the same language.
- **Self-hosting on Cloudflare.** Step-by-step guides (English and German) for running your own relay on Windows, including the free-plan limits and capacity. See [self-hosting-cloudflare.md](../self-hosting-cloudflare.md).
- **Generated screenshots** in the quick start and setup guides (English and German).

## Compatibility

- **Protocol v3 is unchanged.** 1.0.0 talks to 0.1.0-beta.3 components and relays. Components before beta.3 (protocol v1/v2) are told to update.
- **Lobbies need the updated Cloudflare relay** (`relay-cloudflare/`). The Node relay (`relay/`) supports invitation rooms only, without lobbies and the public list.
- **Old invitation codes still work**: viewers paste them under **Advanced > Invitation**, hosts get one for a room that existed before lobbies.
- **Rooms stored in old layouts migrate once** into `coop-local.json` the first time the new component loads such a layout.
- The community relay is preset and comes without availability guarantee. The relay operator can technically see timer data (splits, PBs, game, category); there is no end-to-end encryption.

## Upgrade notes

1. Close LiveSplit. Back up your splits and layout.
2. Replace `Components/LiveSplit.Coop.dll` with the one from this release.
3. Start LiveSplit. A room saved in a layout by an older version moves to `coop-local.json` automatically and reconnects. Check the role in the Coop component's settings (Host or Viewer).
4. Everyone who uses lobbies must use a relay with the lobby API: the community relay, or your own updated Cloudflare relay (`wrangler deploy` from `relay-cloudflare/`). The Node relay stays valid for invitation-only groups.
5. Delete `coop-local.json` only if you want to forget all remembered lobbies.

## Downloads

- **LiveSplit.Coop-v1.0.0.zip:** the component and documentation. Copy `Components/LiveSplit.Coop.dll` into an existing LiveSplit installation.
- **LiveSplit.Coop-relay-v1.0.0.zip:** for self-hosting. Node relay (source, lockfile, Dockerfile, Compose examples) and the Cloudflare Worker (`relay-cloudflare/`).
- **SHA256SUMS.txt:** checksums for both archives.

No credentials, LiveSplit application binaries, game autosplitters, personal PBs, saved runs or logs are bundled.

## Known limits

Running digits can trail the host by network delay. Histories, icons, scripts and layouts are not transmitted. Passwords protect lobby access but are not individual accounts. Some networks (for example corporate proxies) block `*.workers.dev`. A viewer must not run an autosplitter while following.
